## 一处归档勘误

原 `FROZEN_BASELINE.json` 的 `profile_sha256` 对应 Windows CRLF 换行导出件：

`bee4a7129232809a6c224e77b82ac4bc81f919a30f3f3175eecf41596d4c2f6f`

GitHub/g1 的同一 JSON 使用 LF 换行，应按以下指纹校验：

`dbcf85fe3c86ae21972d4f5b79638018ca44f46a39b8cb1e14e8b6cff3a31a8a`

已验证仅换行不同，参数内容相同。`AUDIT_SEAL.json` 同时记录两种字节表示和与换行无关的 JSON 内容指纹。冻结提交不动，追加本说明，不为此改算法或重新生成数据。

## 不能声称已经消失的范围边界

1. 颜色/HDR 与 depth/segmentation 没有统一为完全相同的 renderer 子像素采样；覆盖率仍是近似，并非精确还原全部抗锯齿采样。
2. 两个真实端点之间独立发生、又未被采样的光照或阴影变化，无法仅由端点唯一恢复。已知亮度 ramp 修复不等于这一信息缺口被解决。
3. 当前验证的几何输入按 object/link 刚体位姿处理。柔性条带与流体的连续形变没有对应的已验收支持，B/C 的物理 demo 不能充当事件重建验证。
4. EVK4 标定、正式多 seed 抓取成功率和生成器排名尚未由本次修复证明。

这些必须写清楚，但不必因此继续无限修补现有刚体基线。A 的刚体反弹任务可在冻结核心上做新场景验证；碰撞和明暗变化应遵守输入采样契约。B/C 的新能力需要单独评估，不能提前承诺永远不需要适配。

## 冻结后执行规则

锁死提交和显式生成配置 `coverage_time_log_linear`。后续推进场景、数据、模型和统一控制器；不要因为某个分数不好就再次改生成规则。若发现违反既定契约的可复现错误，或决定增加新能力，只能另开版本，不覆盖本论文冻结基线。
