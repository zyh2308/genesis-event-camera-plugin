# 更宽分布盲测：32个种子块、四档输入、320次实际回合

本目录只有待执行参数和协议约束；没有运行Genesis、渲染器、事件生成器或控制策略，也没有读取这批盲测的成功/失败结果。

根会话已在计划提交`0e28834`选择 **full32**。本轮评估100/50/25/12.5 Hz四档源图像，每档Ours/V2E分别使用各自在相同开发预算下选出的最佳前端。原权重、冻结事件核心和共同物理场景固定。所有四档均完整报告，不根据中途输赢停测。

## 与原Catch It!采样分布的关系

原源为`upstream/gym_dcmm/envs/DcmmVecEnv.py::random_object_pose`，上游声明提交`b6af28c67586fc029f3ab43faf5d787e7d3a1609`。本目录记录源文件、配置文件及函数AST的SHA；32例均直接执行原函数中位置/速度赋值前缀，与生成器结果逐值相等。没有执行其物理或释放逻辑。

生成公式保持原样：

| 项目 | 原代码分布/规则 |
|---|---|
| x | Uniform(-0.5,0.5) m |
| y | Uniform(2.2,2.5) m |
| 高度 | 等权混合：Uniform(0.7,1.0)与Uniform(1.0,1.6) m |
| 水平基础速率r | Uniform(1,2) m/s |
| 水平角度α | Uniform(75°,105°) |
| 水平速度 | vx=r·cosα；vy=−r·sinα；当y>2.25，再令vy减0.4 m/s |
| 竖直速度 | Uniform(2,2.5) m/s；当高度<1.0，再加1 m/s |

**没有设置固定车道，没有按横向位置把速度指向中心，没有裁掉向外或较难的轨迹。**

抽样方法为x四等分×低/高高度×基础水平速率两等分×y两等分，共32个等概率分层，各层内均匀抽一例，角度和竖直基础速度独立均匀。完整因子组合各一例、层权重均为1/32，因此这些因素的联合分层概率与原分布相符，各边缘范围及混合权重保持。

这是**原目标分布的等权分层设计**，并非按原全局NumPy随机数消耗顺序得到的32个iid reset。每例种子和launch参数公开预注册；不得声称相同seed未经override的原reset会产生同一个位置/速度。

本次实际参数跨度：x −0.4756至0.4852 m；y 2.2039至2.4986 m；高度0.7060至1.5218 m；vx −0.4138至0.4792 m/s；vy −2.3334至−1.0278 m/s；vz 2.0375至3.4009 m/s；总初速2.3828至4.0157 m/s。其显著宽于旧±0.35附近小抖动的双侧bank。

## release和世界重力不能在本地冒充实测值

`--launch-config`当前只覆盖位置和速度。原runner先按episode seed执行正常reset和`original_random_pose()`，之后覆盖这两个字段；原先的object_static_time、quaternion、gravity、PID、噪声等随机数调用仍保留。

原reset的计划释放阈值支持为0.5–0.75 s，世界重力z支持为−10.31至−9.31 m/s²。本bank对应的实际字段全部为`null`，不会本地猜测或人为指定。

运行时记录并按种子块核对：

1. `scheduled_release_threshold_s`：reset产生的`object_static_time`。现旧runner的`initial.release_time_s`实际表达这一阈值。
2. `actual_applied_release_time_s`：真实物理步首次施加投掷速度的时间；受2ms物理步量化影响，不能把计划阈值直接叫精确实测开球时间。
3. `actual_world_gravity_m_s2`：本回合实际世界重力；同block各方法必须相同。作为已知公共世界参数可供双方估计器使用；释放标记/时刻不得进入感知或控制。

随机种子通常会提供释放时刻变化，但尚不能承诺本32例的真实跨度。只报告实际观察到的跨度，绝不为凑覆盖范围而替换种子。

## 运行协议

| 项目 | 固定要求 |
|---|---|
| 场景 | 原移动平台/机械臂/手、固定7°相机、4cm半径球、asset seed1702、normal lighting |
| 物理 | combined共同接触配置；外层步2ms、控制25Hz |
| 输入 | 每集首帧实际RGB-D初始化；随后事件与机器人自身状态。初始化失败计入任务失败 |
| 原策略/生成器 | bank内的原检查点、冻结core/profile、native V2E源码/检查点SHA保持 |
| 前端 | `ours@100/50/25/12.5`与`v2e@100/50/25/12.5`共八个选择，须在第一条盲测结果前冻结源、配置、开发集和选择依据SHA |
| 每block主条件 | 两来源×四频率，共8次实际回合；每条件一分母，不把频率重复当独立新seed |
| 每block参考 | 含噪GT原策略参考、仅初始化各1次，共2次，可跨频率复用，复用不增样本量 |
| 全部计数 | 32个block，256个主条件回合＋64个参考＝320次实际回合 |

`primary_condition_order`预先采用正向/反向均衡轮换：每个条件在八个顺序位置各出现4次；每档来源先后各16次。根会话可按资源将block并行分片，但不得根据当前输赢改变block集合、前端或评分。执行器对整数频率字典键可用`format(rate,'g')`得到`100/50/25/12.5`，避免把100.0误当不同档位。

不按GT可达性或GT策略成功与否筛样本。初始不可见、初始化失败、物理不可达、原策略失败和来源失败均保留。基础设施错误可以原seed/原冻结配置重试，原失败尝试也留账；不能换成更好seed。

保留原2.5s任务和当前末控制步手球接触主评分。末控制步接触是40ms内存在真实接触，不自动等于连续0.5s保持。连续保持/滑移可由现存trace作补充结果，不在看过盲测后改变主要成功定义。

主图应完整显示四档成功率曲线及逐block配对结果。统计独立单位是32个种子块；如给整体平均差/置信区间，应按block成组重采样，并保留每block跨频率的相关性。不得从四档中只挑最好的一档改称全部方法的普遍排名。

bank中保留的`preset_half=A`只是未采用的历史预算备选：根会话已选full32，本轮不能用它作为看到结果后停在16例的理由。

## 排程粗估，不是GPU累计时间或生产吞吐量

旧25Hz共12个事件回合的三个作业占卡墙钟为451.01/459.15/466.60 s；旧12.5Hz对应443.00/445.03/445.59 s。合计24回合平均约112.93 s/事件回合（含CPU物理、生成与进程开销）。

仅按这个旧测量数量级估算，256个事件回合约8.0占卡作业小时，64个参考另计。三张卡持续可用时建议预留约3–4小时以上，资源、编译或IO变化可能更慢。100/50Hz及本轮最佳前端的实际成本还未测，这个估计不能当成四档实测结果或GPU kernel累计时间。可先用开发回合测成本来安排资源，不能用blind成功率来决定是否完成320例。
