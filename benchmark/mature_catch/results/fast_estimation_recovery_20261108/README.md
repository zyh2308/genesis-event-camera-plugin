## 找到的主要原因

旧机位使球在飞行中段离开有效视野。检测结果的最长时间间隔约为 291 ms，期间控制器主要依赖先验和运动预测；画面边缘的残缺轮廓又可能把距离算错。仅调过程噪声、扩大速度先验范围、直接换轨迹拟合，都没有稳定修好整条闭环。

新的固定机位让高速回合的目标观测最长间隔降至约 20 ms。我们在同一初始来球条件、接触前相同的 17 个控制时刻比较实际闭环状态：

| 感知设置 | 位置误差中位数 / P95（mm） | 速度误差中位数 / P95（m/s） | 实际接取 |
|---|---:|---:|---|
| 原机位、原估计器 | 71.8 / 180.7 | 0.332 / 0.428 | 失败，无手部接触 |
| 原机位、边缘轮廓过滤 | 63.7 / 130.4 | 0.224 / 0.349 | 失败，接触 1 步 |
| 原机位、过滤＋轨迹拟合 | 17.0 / 51.9 | 0.149 / 0.243 | 失败，接触 3 步 |
| 相机上仰 7°、原估计器 | 9.2 / 54.8 | 0.093 / 0.334 | 成功 |

这些是各自真实闭环生成的观测与状态，不是同一事件张量的离线模型比较。位置/速度误差的参考为实际物理状态，不依赖合成参考事件的相似度。完整共同查询数据见 PAIRED_FAST_STATE_METRICS.json，图为 paired_fast_state_errors.png。

因此本轮选择以完整物理接取为验收：轨迹拟合能降低误差，但单独使用仍未留住球；固定机位改善连续观测后，原估计器完成了接取。

## “过早判断抓住”是否修好了

单独增加持续采样和可撤销的持握假设，没有挽回旧机位的逆光失败。该回合只发生短暂接触，进入了按手部传播目标的假设，但后续没有检测到足够的矛盾球体观测来撤销它。受控单元检查中的撤销功能有效，实际这条回合没有触发，不能把它写成已验证的成功修复。

最终候选仍把近手判断视为内部状态传播假设，成功由独立的物理评分决定。正常 1.7 m/s 回合只在 44/63 次控制查询有可用状态，后段使用既有的零增量动作回退，物理接取仍成功；其余三个上仰机位回合为 63/63 次可用。可用状态包括初始预测和手部传播，不等于每次都有新鲜事件。

本轮的直接进展是通过更可靠的接近阶段观测，减少了“速度估错、擦碰后误以为抓稳”的失效链。一般性的持握确认仍需进一步验证，当前不采用尚未证明有用的撤销候选作为默认配置。

## 改了什么、如何核验

这里的“原权重”是 Catch It! 控制策略；“原估计器”是本项目上一轮的已知球径事件估计器，不是上游的 RGB-D 感知器，也不是此前 R1.5 方块热图模型。

最终候选只启用固定的 7°传感器俯仰。相机没有跟着球的真值转动；位置、分辨率 640×480 和垂直视场 58°保持不变。实际归档首帧变换的审计显示：平移变化为 0、内参变化为 0、相对旋转与 7°的最大矩阵误差约 2.7e-8，初始来球物理条件一致。见 CAMERA_PROTOCOL_AUDIT.json。

四条最终候选回合都仅在 reset 读取一次实际 RGB-D；初始球心误差约 1.18–1.33 mm（理想 Genesis 深度，未做真机标定）。随后控制只使用事件估计和机器人自身状态，缺失状态时使用同一动作回退。球体持续由 Genesis 物理推进，终点原始记录和近景均保留。

事件仍由 100 Hz 原生 scene-linear HDR 稀疏端点经过原冻结 CUDA 重建生成。没有用高频 Direct-HDR 替代；没有重新训练控制网络、改变球速来迁就结果或放宽评分。17 个冻结核心文件重新核验通过，六项几何、状态、持握撤销、拟合与未来输入隔离检查通过。新增代码均为任务感知/机位适配及记录，冻结核心未改。

推荐设置见 RECOMMENDED_CATCH_CONFIG.json：pitch=7°，原估计器；轨迹拟合、边缘轮廓过滤和可撤销持握均关闭，保留本轮失败候选代码与数据供复现。
