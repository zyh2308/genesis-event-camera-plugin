## 独立本地追踪

用原只读输入缓存、当前候选代码，在已有 Python 3.10 / NumPy 2.2.6 / Torch CPU 环境重建中点的 NumPy 支持判定。两集的本地 CPU 掩码与保存 CPU 掩码完全一致。

将可信判定拆成：两端点 coverage、首层表面身份一致性、跨端点表面 ID、深度匹配。106 个保存差异点中，82 个点的 CPU 端点1 coverage 距 .995 门槛不到 .0001。CPU 拒绝而 CUDA 接受的 37 点中，35 点在 CPU 端因端点1 coverage 略低于 .995 被拒绝；另 1 点因表面一致性，另 1 点因表面 ID 和深度匹配。

这支持先查覆盖率临界判定。例子包括 .9949776、.9949945、.99499965 与门槛 .995 的比较。但现有 NPZ 没有 CUDA 的覆盖率、投影、深度/表面分项，只保存了最终掩码。因此尚不能证明全部 106 点都由浮点误差造成，不能替 GPU 路径判定根因。

逐点 CPU 侧记录见 mismatch_pixels_cpu_trace.csv，独立统计见 audit.json。

## 下一轮建议

本轮是确定修复规则后的工程一致性收尾，不需要重新扩大模型、训练或场景搜索。

1. 对 106 点及少量邻点补存 CPU/CUDA 的投影坐标、覆盖率、深度分层、表面身份和最终拒绝原因。以同一组投影输入喂两种合成器，再比较各自投影：分清差异来自投影，还是后续累加/分层/比较。
2. 优先处理临界 coverage，同时单独处理表面/遮挡案例。统一关键计算精度、取整、分层与临界判定语义；如需不确定带，依据误差界和原有可信含义设计，临界信息不足仍应标未知。不能仅放宽 .995、删掉差异点，或复制一边掩码伪造一致。
3. 局部修复后重跑同一验收，并加入一组贴近门槛的微扰样例，确保没有重新引入“极小贡献决定整像素”或把无依据区域标为可信。若想调整 exact-mask 验收标准，需明确它允许的差异是否改变补渲染/事件路径，不能事后静默改标准。
4. 把缓存 warp 输出也分别经过 CPU/CUDA DVS，补齐四种组合的像素/极性与时间比较。允许已声明的有限时间误差，不把总事件数相同写成事件数组相同。
5. 通过后结束后端一致性这一项。另行验收实际中间亮度采样与补渲染成本，不能将此单项通过当作整个核心可冻结。当前 permissive 缓存回放没有 renderer，且 photometric_spacing_satisfied=false。

本研究侧未连接服务器或重跑 CUDA，没有修改候选核心或训练模型。结论依据已归档 GPU 数组、日志与独立 CPU 重算；没有给诊断会话发送消息。
