# 原稀疏重建路径：像素定位修复实测

本轮达到预先写定的定位改进标准。生成和训练只使用原有低频 HDR 端点及深度、分割、相机／物体位姿，中间画面由插件的几何重建产生。没有高频 HDR 补图，也没有 capture_observed 入口。高频 Direct-HDR 只作为所有模型共享且保持不变的测试事件输入。

## 实际结果

单位为原始 320×240 图像像素。P95 表示 95% 查询的误差不超过该值。所有查询计入；没有按可达判断或预测置信度筛掉难例。

|---|---|---:|---:|---:|
| 主评估：9 条轨迹／581 个查询 | 旧 Ours | 8.18 | 106.72 | 225/581 |
| 主评估：9 条轨迹／581 个查询 | 稀疏重建候选 | **2.33** | **5.77** | **3/581** |

12 条轨迹逐条检查：候选的中位数与 P95 均低于旧 Ours。主评估 581 个查询全部有效，补充 193 个查询也全部有效。它们是开发与归档复查材料；这些结果支持本轮修复有效，不作为正式生成器排名或抓取成功率。

## 改了什么

1. 保留原来的稀疏端点几何投影与按面积合成；中间亮度按时间和投影覆盖程度连续融合，避免整个区间直接拿后一帧的亮度。
2. 未充分覆盖的区域继续保留“未知”标记；在原有近似重建模式内连续估计，避免区间中点突然从前一帧切到后一帧。0.995 支持门槛未放宽，严格模式仍拒绝没有观测支持的重建。
3. 区间两端保持真实输入值，避免把已经观测到的端点再经过一次投影而改变亮度。

改动在 physics_warp.py 与 physics_interpolator.py，启用名为 coverage_time_log_linear。没有修改网络结构、解码器、标签、控制器或测试事件。原 strict sampled 模式也没有被当成这次修复。

## 为什么可以计作稀疏算法修复

运行经过公开 capture → PhysicsInterpolator → 几何投影重建 → DVS。9 条训练／验证轨迹共读取 1,814 张原有端点图；回调读取时刻与原缓存逐项相同，新增渲染和高频帧读取均为零。事件未按目标掩码、标签或误差做筛选。

同样的 heatmap_v2（35,261 参数）、seed 606、40 轮、batch 32、训练／验证拆分及模型选择规则；训练 1,203 个窗口、验证 566 个窗口，模型由自身验证集选择第 36 轮。在测试前锁定 checkpoint。高频参考事件没有进入生成、训练或模型选择。

受控检查包括：静态零事件、精确端点、已知亮度变化的事件时刻、几何平移、覆盖不足仍标未知、严格模式拒绝未知区域以及公开接口仅访问两端点。逐查询像素距离另行从预测坐标复算，V2E 对照与原始评估一致。

亮度机制对照中，10 ms 的已知 log 亮度变化，应在 2.22／4.44／6.67／8.89 ms 触发阈值；旧 next_primary 在约 0.25／0.49／0.74／0.99 ms 就触发，候选回到应有时刻。该对照证明时间处理的修改依据，最终验收仍用上表的定位误差。

## 当前可下的结论

原稀疏 CPU 路径的本轮修改已显著减少接触前定位误差，并在另外三条归档轨迹上复现。CUDA 新模式尚未实现（显式拒绝，不会静默走旧路径），也尚未重跑抓取控制。这两项与本轮已完成的像素定位验证分别记录。

像素响应仍为与原实验相同的理想、未标定 profile（正负阈值 0.2、无噪声）；没有更改 real_v2 校准默认值。
