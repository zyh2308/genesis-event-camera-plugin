# EventGenesis：论文效率实验调研与补充方案

日期：2026-11-05。状态：文献与实验设计完成；扩展实验尚未执行。原五场景测量属于已有证据，不能写成扩展实验的结果。

## 1. 研究结论

建议补充“事件数据生成的计算效率”实验，以实测时间、显存和质量取舍说明价值。本文设计是结合文献形成的研究建议，不是 CVPR 统一规定的实验模板。

当前可以支持的表述是：**在指定 V100S、五个固定片段和相近高密度中间采样设置下，缓存物理输入到 CPU 事件输出的耗时，相对 v2e + SuperSloMo 的配对提速几何平均为 2.556 倍。** 它不能改写为“同物理精度下全面快 2.56 倍”，也不能改写为完整 Genesis 场景实时运行。样本仍少，且显存代价明显。

必须同时展示 v2e 官方自动采样运行点。它目前约 0.500 秒处理 0.200 秒片段，与高密度运行点不是相同计算工作量；没有完成质量测量前，不能断言它达到或达不到同等质量。中间图像间隔、输出时间戳的存储单位、事件时间的实际误差是三个不同概念。

## 2. 文献核查：哪些成熟做法值得采用

本次检索覆盖 CVPR/ECCV 主会、相关 CVPR Workshop 与 ICRA，共十篇。研读重点是论文的实验段落、表格、补充材料和官方实现。AMiner 接口未配置凭据，使用公开原始来源完成检索；未使用第三方论文笔记作为证据。

这些文献不构成“我们比所有当前方法快”的证据。按已确认范围，主比较保留 EventGenesis、V2E、Vid2E、FILM+ESIM、RIFE+ESIM；Texvent/SENPI 等近期方法进入相关工作与候选补充对照清单。如论文拟声称“当前最快”或覆盖整个领域，则必须扩展并重测近期方法，五方法表不足以支持该声称。

## 3. 补充实验：主文一张表、一张图，附录一个消融

### 3.1 主表：完整事件生成时间与资源

主问题：**从同一物理过程获得可用事件，实际花多少时间和显存？**

比较项：EventGenesis限定高速版本；V2E+官方SSM；历史Vid2E的SSM+GPU ESIM；FILM+同一GPU ESIM；RIFE+同一GPU ESIM。后面三项明确是插帧后端与同一事件模型的组合，不能包装成三个独立传感器模型。当前 Vid2E 仓库若采用 FILM，不重复计为另一个独立方法。

每个方法报告两类运行点：①官方推荐/默认时间采样；②接近已冻结 EventGenesis 中间采样工作量的高密度设置。EventGenesis 保持冻结传感器参数和采样器；两类设置若完全相同，仅报告一个点。**工作量接近不等于精度相同。** 对不能原生实现相同时间请求的插帧器，记录实际采样时刻、最大间隔、生成帧数、递归规则和端点约定，不强行改模型凑数。

| 表内指标 | 定义与用途 |
|---|---|
| 总生成耗时，s / simulated-s ↓ | 片段墙钟秒数 / 物理秒数；越小表示数据生产越快。 |
| RTF ↑ | 物理秒数 / 生成墙钟秒数；1才代表实时。与上一列互为倒数，主文择一以免冗余。 |
| 峰值显存，GiB ↓ | 测量工作进程 Torch allocated 峰值，另保留 reserved 与设备进程观测；跨框架以同一设备进程口径补报，不能把 TF 未统计写成0。 |
| CPU峰值内存，GiB ↓ | 独立工作进程及子进程树的内存口径与工具版本；不能只看主进程而漏掉子进程。 |
| 事件数与实际中间帧数 | 用来解释工作量和功能差异，不以输出事件越少为优势。 |
| M events/s，补充列 | 事件数 / 时间 / 1e6；不同生成器事件密度不同，不能作为唯一速度排名。 |

三种边界分别报告：

1. **warm cached generation（主对照）**：相同已加载的CPU物理缓存/视频帧 → 插值、几何、传感器、必要搬运和排序 → CPU原始事件数组。排除渲染、进程/权重启动、输入磁盘读取、输出磁盘写入。EventGenesis需要的几何上传成本计入；基线的插帧不能排除。
2. **native end-to-end（附表）**：物理步进/Genesis原生渲染 → 各方法所需输入 → 同一格式写出，另计共享渲染与方法特有采集成本。深度/分割等输入若有额外开销须归属EventGenesis，不能借“共享”掩盖。
3. **cold start（附表）**：新进程到首段事件完成；权重加载、JIT编译、初始化及I/O分项记录。首次编译与已有编译缓存分开，不拿它与别人的warm计时相除。

输入信息不同是方法能力的一部分：EventGenesis使用HDR、深度、分割、位姿；视频基线使用同源视频。两者对应相同物理轨迹，不宣称使用完全相同的输入张量。这些信息不进入下游模型推理输入。

### 3.2 图：耗时与质量的关系

不直接画“FPS越高越好”或只放固定377子步结果。展示官方运行点和预登记的时间采样运行点，横轴为实际生成时间，纵轴为可验证的质量。

优先复用已有合成精度评测：同一可见表面上，使用**独立高频直接渲染/解析运动参考**，比较中间图像误差和运动边缘定位误差；按遮挡、显露区域单列覆盖及失败率，不把unknown像素当作正确结果。参考时间点不用于插值输入，参考不能由EventGenesis自己的输出生成。参考渲染频率先做独立收敛检查。

质量图首先标为“插值质量—总生成耗时”，明示中间图像指标仅描述插值，不能等同完整含噪事件的真实性。完整事件层面沿用已冻结的事件相似度协议；若跨传感器模型的参考、时空单位和噪声统计无法公平核验，就分别展示相似度与速度，**不发布同质量速度排名**。

V2E候选点为自动采样、最大中间间隔1ms、0.1ms以及与约26.5us密度相近的受控点；重复点去重。Vid2E/FILM/RIFE采用其原生支持的邻近点，实际间隔逐个记录。EventGenesis高速版本先保留冻结的一个运行点，不能为曲线临时改变带宽、噪声、遮挡规则或以参考回退冒充高速入口。

公共MVSEC/HQF/HS-ERGB/E-POSE测试不用于挑选上述运行点。三项最终Sim-to-Real表独立证明训练数据的实用性，无需为每个插帧密度额外训练三项网络。若没有可比较的质量，主表明确只能回答限定工作量下的效率问题。

### 3.3 消融：加速来自哪里

在同一冻结输入与配置下，比较原参考实现、融合传感器核、GPU常驻完整实现，列总耗时、几何/插值、传感器、搬运/排序和显存。只列有可复现实现与正确性证据的行，不用不同场景的提速相乘。

分阶段profiling可能引入同步与计时开销，单独运行；总墙钟计时使用不插入额外中途同步的原生路径。并行重叠阶段不强行加和到100%。精度列保留raw float64门禁失败、原参考自身的重复运行波动，以及已经通过的写出/输入表示检查。

## 4. 固定工作负载与统计

- 扩展至20条独立合成rollout：四类rich场景各4条，匹配E-POSE物体场景4条。优先使用已冻结缓存；选取方式为排除已有五条之后，按预登记seed与rollout ID的哈希顺序抽样。先保存完整清单与输入哈希，再运行，不能按结果选场景。不足四条则先报告不足，不能悄悄换样本。
- 每条主测片段0.2秒，起点由可用范围和固定抽样规则在测量前确定。保持rich与pose各自原生320×240或346×260，按分辨率分表；同一场景所有方法的分辨率必须相同。不得拉伸图像后声称原生物理缓存不变。
- rich每类预先固定一条，另测0.4与1.0秒以检查短片段固定开销。主结果始终保留0.2秒，不事后只留最有利时长。
- 同一g1 V100S，单任务预约，记录GPU UUID、驱动/CUDA/Torch/TF、CPU、线程数、精度、编译参数与batch。固定batch受控表与各自合理batch吞吐控制分开。不升级共享环境、不访问当前禁用的g3。
- 每个运行点每片段至少3次独立episode重复，轮换/随机化方法顺序，保存全部记录。预热后重建episode状态和固定RNG；预热事件不进入结果。开始/结束显式CUDA同步，测墙钟。
- 以每片段三次中位数作主估计，保留均值、标准差、IQR和全部单次值；配对提速使用log-ratio几何平均。按rollout/场景分层bootstrap95%区间，不能把相邻帧当独立样本。固定四类rich与一类pose的等权规则在测量前登记；同时列各层结果。
- OOM、非法输入、数值异常、超时、参考回退均保留。超时上限必须在首轮测量前登记，不能将失败点记成0秒或删掉。共享服务器被其它任务打断时保存该次并按事先规则标记干扰，不按耗时大就任意剔除。
- 归档每个方法源码commit、checkpoint SHA256、命令、实际采样时间、profile、输入/输出哈希、原始逐次计时和资源观察。不要从论文表格抄速度与本机数据混排。

## 5. 当前证据与尚缺部分

已有固定五场景的高密度静态入口结果：EventGenesis每0.2秒片段耗时12.079–22.281秒，v2e45.897–48.953秒；配对提速几何平均2.556，场景重采样区间[2.263,3.140]。EventGenesis Torch allocated峰值7.182–11.000GiB，v2e约0.754–0.757GiB。不能把这些资源数字外推到其它分辨率或框架。

V2E自动采样约0.500秒是单场景额外控制，不能与五场景汇总混成一张无条件排名。双方高密度路径都远未实时。现有流程未覆盖五种管线的完整Genesis端到端耗时、20条扩展样本、FILM/RIFE/ESIM完整配套和质量曲线；这些单元格留空。

已有证据：[效率对照报告](../simulator_efficiency_comparison_20261105/EFFICIENCY_COMPARISON_REPORT.md) · [逐次计时](../../evidence/20261105-efficiency-comparison/matched_suite_static_timings.csv) · [冻结说明](../../../../frozen_versions/eventgenesis-gpu-stage9-20261105/README.md)。该报告中此前使用的“同采样精度”表述应理解并更正为“相近高密度采样工作量”，尚不是实测同等物理精度结论。

## 6. 执行顺序与论文表达

先锁定抽样清单、计时边界、基线版本与三线输入表示核查；再补推荐运行点和五管线暖启动表；随后完成质量诊断与端到端附表。已有真实测试及训练不为速度实验中断。数值图用CSV/LaTeX与PDF/SVG输出，不在本轮增加架构图或demo。

建议当前论文表述：

> 在固定高密度时间采样与完整传感器设置下，GPU常驻实现降低了事件生成耗时。五个固定片段的先导测量相对v2e+SuperSloMo得到2.56倍几何平均提速，代价是更高显存；该计时从已加载物理缓存开始，不包含Genesis渲染。不同默认采样配置的质量与效率另行比较。

扩展实验未完成之前，不删除“先导”“指定设置”“不含渲染”等限定，不声称当前最快、完全GPU渲染、实时仿真或更高Sim-to-Real精度。三线重训条件见[下一轮训练准备](RETRAINING_READINESS.md)。
