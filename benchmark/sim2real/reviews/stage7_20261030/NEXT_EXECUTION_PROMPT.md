## 光流：本轮必须从旧单窗诊断转向丰富场景与多窗口训练

Stage 7 的 200-update 日志与独立验证已验明有真实产物，不重跑。它仍是旧棋盘/方块场景的一个训练窗口，不能满足场景升级。EG 在训练窗 active EPE 仍是零流约 7.47 倍，报告统一称为“监督目标下降、未建立有用运动学习”，不要仅因内部 loss-ratio 门槛通过就写“学会了”。

**首批交付是一个成熟室内场景真正进入 Genesis，并渲染出有广泛可观测运动的短片。**

- 先取得 ReplicaCAD Interactive/PBR 一个完整布局及其模型、纹理、材质；固定来源/revision/hash。若 WSL 的 HF 路由仍失败，尝试现有可用代理或 Windows 下载后传 g1，不要求本地也安装 Genesis。GitHub 代理能用不等于 HF 已通。不要因一次旧连接失败连续多天退回方块拟合。
- 已有可用成熟室内资产可以替代，但必须记录来源与许可；如 ReplicaCAD 结构性不兼容再换 HSSD。不要同时搭建多个仿真平台，也不能只下载 RGB 视频替代物理 bank。
- 首场景交付 RGB、深度、GT flow、两组事件以及相机路径预览；固定共同色标，能看到家具、纹理、不同深度及持续相机平移/旋转。检查尺度、坐标、白模/丢纹理、穿墙和可见性。静止相机下小物体运动不能再次充当全部场景。
- 后续约三个布局起步，至少 2 train / 1 validation，包含多条轨迹、多时间窗口；按完整布局/轨迹分组，不能相邻窗口随机拆分。少量布局是学习性 pilot，不声称足够支撑最终跨住宅泛化。按固定种子/规则抽样，不看 generator 或真实排名挑场景。
- 启动前报告实际 crop/增强后的 GT 位移、非零运动、纹理/运动交集及无支持比例。动态纹理支持不能还只有几十像素。验收条件用共享物理统计预先登记，不通过则先改共用相机路径/距离，不能用加噪声或按某组事件数筛样本“增加信号”。静态/无事件窗按登记规则保留，不后验丢弃。

**研究侧已批准新版主训练采用共享合成 GT 监督。** 先保持 STE-FlowNet 架构，复用已有四尺度监督 loss，推进多窗口、多轨迹训练。GT 只作训练标签/离线指标，网络推理仍 events-only。原自监督版本归档；这轮无需把恢复原光度自监督目标当成进入多场景训练的前提。新 run/config 清楚注明目标变化，不与原 45 epoch 结果混称同一协议。

- 注册两组同初始化、同样本/增强顺序、同预算的训练。建议以各 1,000 updates 作为有上限的首轮多窗口 pilot，登记 update 0/200/1000 的合成诊断；如资源/实际速度需要调整，在启动前固定新预算，两组一致，不按结果偏袒一边。
- 完整独立场景/轨迹报告 EPE、零流、normal/zero-events/reverse-bins、预测/GT 幅值与方向，分开全有效区、固定共同 active 区和运动区。正常输入是否优于清零、是否预测出运动，比只看 loss 下降更关键；反转不一定必须变差，照实解释。
- 对已完成单窗 run 的恢复检查，修复 driver 中被转义的 `${arm}`，先检查实际路径，再独立进程 restore + one optimizer update。保留 exit 1 历史。此事只应是一次小检查，不重做 200 更新，也不阻塞下载和场景准备。CPU 可做 checkpoint 元数据/状态核验，但不能把 shim 成功写成 CUDA 成功。
- 实际核实 renderer 输入：能否使用已有 frozen-compatible HDR overlay/float signal adapter，记录 tensor dtype、范围、曝光/量化链。默认 API 的 uint8 经逆 gamma 仍是 proxy。原生路径尚未恢复可做标明限制的几何/训练诊断，但不能把 proxy 版本宣称为原生 HDR 正式实验证据；该问题单列为研究方法待解决项，不能藏在普通兼容报告中。

MVSEC 仍保持未评分；待新版数据、训练和 checkpoint 选择在合成域冻结后再进入真实测试。下载/转换/未评分全窗口注册可独立准备，不等 outdoor 下载才做合成学习。

## 位姿：落实标签修复与合成训练，不再停在两个相邻样本的审计

批准版本化的 E-POSE 几何 label adapter；原数据只读保留，不覆盖。

- 从核验 CAD、逐时刻 object-to-camera SE(3)、K/畸变和官方时间同步资料生成标签。新增标签与原 MAT 2D keypoints 的差别明确记录，不能把 corrected 协议结果冒充未经修改的原始官方 benchmark。
- 统一坐标域：原始畸变事件使用相应 K/D 投影，或统一去畸变事件并用对应 K' 投影。不要对理想针孔投影再次不加区分地去畸变，也不能只改投影分母就开训。导出逐点 stored/ideal/corrected UV，区分欧氏重投影均值和坐标 MAE。
- 官方代码的 `cameraPose` 固定索引需在派生层修正，但不要因此随意改已核验的逐样本 object pose。100 ms 可能是官方时间校准：核对本地 `E_Pose/time_shift_used.ods` 与准确序列名/时钟原点，不能机械删除，也不能所有序列套一个 block 偏移。不以模型分数重新估计真实同步参数。
- 按事先固定的序列和均匀时间索引扩到早/中/晚时刻及不同运动条件做几何自检，避免只看相邻 10 ms。导出器关键公式、坐标/时间与重投影自检须有可运行代码入库；两行 summary 不替代脚本。
- 先在 wood block 及另一个 CAD/类别对应确定的对象上建立共享 Genesis 合成训练/验证；wood block 的对称性会影响方向可辨识性，ADD/ADD-S 与旋转误差解释应明确。优先让已核验对象跑通，未知对象不挡住全部线路。
- 小规模配对训练、多窗口/独立 rollout 普通 eval、置信度选点/PnP、checkpoint 恢复均有实际证据。输入是全帧事件及事先声明可获得的先验，禁止 GT crop/mask/box、GT 选点或用真实标签挑 PnP 候选。真实标签仅离线接口/评价用途，不用于学习。E-POSE 候选模型真实评分仍关闭。
