# 训练前正确性复核：确认问题并前移验收

日期：2026-10-17。基于提交 `ce2333128b5a203412b4e3aa80ca355fd669c07b` 的 Stage 4 数据和实际 g1 运行环境。

**结论：原先两项发现均确认；另确认 renderer 输出的深度、内参和像素坐标之间存在几何契约问题。旧数据/代码组合保持 BLOCKED，不应直接再跑 45 epoch 或扩 seeds。** 没有修改冻结 simulator core，没有修改训练代码，没有开启新训练或真实数据评分。

此前验收过多依赖更新次数、有限梯度、配对 hash 和 checkpoint 可读，没有检查实际 renderer 身份映射、已知运动和 warp 恒等性。这是研究验收设计的不足；本次将其转为训练前可以执行的检查。

| 检查 | 范围与结果 |
| --- | --- |
| 原始几何与旧标签 | 全部 32 rollout × 3 端点 = 96 个端点；按当前错误输入重算的 GT 与保存 GT 在旧有效像素内最大误差约 9.54e-7 px，证明错误路径确实产生了本次标签 |
| 数据适配传输 | 64 个 NPZ 全部与共享 bank 的 flow、valid、灰度端点、时间窗一致；这是传输通过，不是物理标签正确 |

这些结果缩小了排查范围，但不抵消下列基础错误。

## 2. 编号错配：确认，直接影响真实 bank

实际 renderer 的 `SegmentationColorMap` 以 `0 → -1` 初始化背景，并为物理 link 编号分配独立的渲染编号。独立执行该实际类，给物理 ID 17、5、42 分配出的渲染 ID 为 1、2、3，进一步证明不能通用地依赖“减一”。本 bank 恰好是背景/地面/盒子 `0/1/2/3/4` 对物理 `-1/0/1/2/3`。

8 个静止相机 rollout × 3 端点共 24 个检查。其中 23 个在旧 valid 内有地面像素，**23 个全部给静止地面标了非零位移**；平均位移范围 0.5042–9.5782 px。地面 pose 完全不变，相机变化至多约 9.77e-9（浮点舍入）。正确映射后，地面平均位移最大约 9.79e-9 px。剩余一个检查旧 mask 没有地面有效像素，未将其冒充通过或失败的位移样例。

源码调用链与上次报告一致：benchmark 把 raw render segmentation 交给按物理 link ID 建键的位姿字典，既用于共享 GT，也用于 EventGenesis 物理插值。原始 GT 在 96 个端点被数值复现，排除了“只是未调用的旧代码”的解释。

## 3. 模型与损失的 warp：两条实际调用路径均确认

本次直接从 g1 实际锁定源码提取损失 `warp` 和模型 `flow_warp/mesh_grid/norm_grid`，保留坐标表达式；损失测试仅去除 CPU 不支持的 `.cuda()`。测试零位移、水平、竖直、双轴整数平移以及梯度有限性。

当前两条 warp 的四项内部 MAE 均约 **0.1075–0.1086**；只把相应调用的坐标约定配成一致后，均约 **9.8e-8–1.2e-7**。模型 forward 在多个尺度确实调用 `flow_warp`；训练 objective 确实调用锁定 photometric loss。这不是 warning 或闲置 helper。

实际环境为 `torch 2.5.1+cu121`。原表达式按 `W-1/H-1` 归一化，却使用默认 `align_corners=False`。工程应明确统一坐标约定，并使用训练中的真实 CUDA 函数再跑相同控制；不可全局把其他采用像素中心公式的增强调用也改 True。

## 4. 新确认：renderer 深度 / K / 像素位置的几何契约不一致

检查保存的深度时发现：用当前 K 和整数像素射线反投影，标为地面的点没有回到实际平面上。为排除 ID、运动或模型的影响，独立创建了**一个静止平面、同一相机配置**，在实际 Genesis 1.2.2 + HDR overlay 上运行两条渲染路径。未训练、未改任何源码，GPU 0 先检查空闲，整个极小实验约 **23.32 秒**。

相机沿用 346×260、FOV 58°、near 0.03 m / far 8 m；平面物理 link 0，渲染编号 1。先腐蚀地面 mask 4 像素以排除轮廓边缘，再检查世界坐标高度应为零：

| 路径 / 反投影坐标 | 地面高度绝对误差 median | p99 |
| --- | ---: | ---: |
| 本次实际 `rgb+radiance+depth`，整数像素 + 当前 K | 5.68 mm | **22.30 mm** |
| 同上，仅采用 +0.5 像素中心对照 | 2.40 mm | 9.45 mm |
| 独立 `depth-only`，整数像素 + 当前 K | 3.23 mm | 12.83 mm |
| 独立 `depth-only`，+0.5 像素中心对照 | **0.065 mm** | **0.180 mm** |

源码中，radiance/color 路径启用多重采样，并把多采样深度 buffer resolve 到单采样 buffer；SEG/DEPTH_ONLY 路径禁用多重采样。记录的 K 主点为 `(173,130)`，投影算法使用整数像素坐标。两条深度路径在这个平面实验中最大差约 0.1149 m。相关实际源码摘录见 `renderer_contract_probe.json`。

因此已确认的是：**把当前组合渲染返回的 depth 与当前 K 直接当作整数像素中心几何输入，不能满足静态平面反投影契约。** 多采样读取与像素中心约定共同提供源码解释；未用当前设备上的某个经验 offset 硬拟合修复。比如组合深度用 +0.875 可降误差，但这不是跨硬件/曲面通用校准，禁止直接把它写成固定修复。

修复应在 benchmark 的 renderer-facing 数据边界明确深度取样与相机坐标约定，并保证插件和共享 GT 同用一份正确几何。独立 depth-only + 一致像素中心提供了可行对照，**尚未接入正式 exporter/插件，也没有宣称完成工程修复**。冻结 simulator core 不应为这个调用方契约问题直接改算法。如发现必须改冻结 core 才能解决，再上报方向性决定。

## 5. 额外数据质量事项：首帧初始化

源代码第 0 帧直接用 base position；从下一帧的 substep 才开始应用带相位的 `trajectory_pose(t)`。对全部移动物体检查得到 32 个初始位置与 `trajectory_pose(0)` 不一致的情况，偏差 0.0568–0.1846 m。

这确认了“预定义平滑轨迹从 t=0 开始”的假设不成立，可能引入首窗瞬态；**不等于所有保存位姿不真实，也不能用它解释所有模型误差**。工程在重新导出前应明确处理：若改初始化，要给两组同一新 latent 版本；若复用原物理记录，必须如实保留并声明初始瞬态。不得只删除某组首窗、事后按表现筛样本或偷偷减少固定窗口数。

## 6. 为什么此前没拦住，以及这次的可执行判定

旧生成器的方向检查只验证手写投影小例子，未经过真实 renderer 的编号和深度接口；augmentation 检查只检验一个手写矩阵；update-20 恢复只比较重新加载模型的推理，没有真的走 `--resume` 后续 optimizer 更新。上述检查各自有用，但不足以放行整个管线。

`assess_captured_audit.py` 对本次独立证据执行数值判定，输出 `gate_verdict.json`；旧组合得到 **BLOCKED，退出码 2**。失败项为静态地面标签、损失 warp、模型 warp、实际 frame-provider 几何；其余受检数值契约通过。脚本还保存了 18 个源码和 4 个输入 manifest/config 指纹。

注意：该脚本是**本次审查证据的可执行判定**。生产 launcher 尚未接入拦截；不能声称已实现无人值守的自动放行。修复与 launcher 接入交给工程会话，具体要求已写入根目录研究交接 `STAGE4_CORRECTNESS_REPAIR_AND_PREFLIGHT.md`。本研究会话没有代写生产实现。

新训练必须在同一代码/数据/配置指纹上完成：小场景物理与算子控制 → 新 bank 与适配检查 → 正式 CUDA 入口有限配对短跑及真实断点续训。全部通过后工程会话可按既有授权自主继续完整训练，**不需要用户再批准一次**。
