先读 `reviews/stage4_preflight_followup/REVIEW.md` 与 `gate_verdict.json`，再结合 `reviews/stage4_completed_ce23331/REVIEW.md`。旧 45 epoch 确实完成，但不能作为有效生成器比较；旧数据/代码组合为 BLOCKED。此次目标是一次处理已知正确性缺陷，并让以后错误在长训练前被拦住。不要修一处就马上再跑 45 epoch，也不增加 seeds 掩盖基础错误。

## 要一起处理的问题

1. **真实 renderer ID 映射**：render segmentation 不是物理 link ID。用实际运行时映射统一插件输入和共享 GT，正确处理背景；不能把当前 bank 恰好满足的 `raw-1` 当通用实现。静止相机/地面的非零 flow 反例必须消失。
2. **STE 模型与损失 warp**：统一坐标归一化与 `grid_sample` 约定，修复实际 forward 和 photometric loss 路径，保留锁定第三方源码及明确的兼容补丁/hash。不要全局改动本来就一致的 augmentation 调用。
3. **depth/K/像素中心契约**：组合 radiance+depth 路径的 depth 及 K 不能直接作为当前整数像素射线的中心点深度。独立静态平面反投影已经失败；depth-only + 一致像素中心是成功对照。选择清晰、可复验的 renderer-facing 适配，插件和 GT 使用同一几何。禁止拿某个设备经验偏移（例如 +0.875）硬凑正确。
4. **启动与恢复**：修复已知 RNG CPU/CUDA 设备恢复问题；提供通用新 run 入口，不能继续依赖旧失败目录专用 retry 脚本。真正比较保存前后继续更新的结果，不能只比较权重加载后的推理。

原冻结 core `e79e656ac00f7847b98db9e12bf43b093f3afff1` 保持不变；先在 benchmark/provider/compatibility 层处理这些接口契约。若确实无法保持冻结 core 再上报。原有模型、训练预算、真实域隔离和 event generator 单变量原则继续执行。

## 按成本由低到高验收

**A. 在新一批昂贵数据生成或正式训练前，用真实运行环境跑小场景与算子控制。**

- 真实 Genesis renderer：背景/非连续 link ID 的映射可逆；静态相机和地面零 flow；物体平移只影响对应物体；用已知平面/已知轴向位移核对 depth、K、坐标轴、u/v 和单位。以独立解析式/真实物体状态作参照，不要用同一个 GT 函数同时生成期望和实际。
- 几何输入：静态平面内部（排除轮廓、near/far 裁剪）反投影应回到平面。研究侧 0.03–8 m fixture 以高度误差 p99 ≤ 1 mm 作宽松初始门槛；独立正确对照约 0.18 mm。说明误差预算，不能简单放宽阈值接纳旧 22 mm 偏差。
- 实际 CUDA loss/model warp：零位移应恒等，已知水平/竖直/双轴整数位移应匹配，内部 MAE ≤ 1e-6，并核对最大误差和梯度；CPU 仅是独立参考，不能代替实际 CUDA 路径。验证 photometric loss 对无光照变化、无遮挡的纹理平移方向和已知正确位移有合理响应。
- EPE 的 u/v、单位、非法输入、padding/unpadding、增强坐标与向量，以及相关算子前向/反向均有简短控制。现有研究脚本有可以复用的通过案例，避免另建庞大测试框架。

**B. 新版共享数据/双方适配完成后，自动核对再开训。**

- 对整个 bank 检查源身份映射、姿态/K/单位/时间范围、split 隔离、标签/mask/灰度/窗口配对和文件 hash。几何抽查覆盖每个 stratum 的 train 与 validation，首/中/末帧；不得只测一个手工小例子或一个已修复样本。
- 原始事件到下游表示的复算须覆盖两组、时间边界、空窗和极性；不根据事件多少删样本。检查训练输入仅有登记事件表示。
- 已知错误会影响 EventGenesis events、共享 GT/valid、适配产物及旧 synthetic-best 选择，不能只换验证标签后沿用旧训练结论。明确新版本依赖：未变的 radiance/display/V2E 原始事件可在证明依赖和 hash 不变后复用；旧 depth 的复用须通过新的几何检查。不要为了省重建把错误几何直接带入新版本，也不要无必要全部重做。
- 首帧未在预定义 `trajectory_pose(0)` 上的问题一并查清。若修正初始化，新 latent 轨迹/双方数据统一版本化；若保留现有记录，明确初始瞬态及适用性。不得事后按排名删首窗或减少某组样本。

**C. 同一正式 CUDA 入口先做有限配对运行，再继续剩余预算。**

- 从登记 seed 0 随机初始化，在两组同一正式配置、数据、采样、augmentation 和有效 batch 下运行有限更新，覆盖训练、完整 synthetic validation、best/last 保存和真正 resume。控制在最多一个 epoch 的初始诊断预算；发现确定的契约错误立即停，不以继续跑满 45 epoch 代替排查。
- 真实断点检查：同一中间状态下，“不中断继续若干更新”与“保存、退出进程、走正式 resume 入口、继续相同更新”比较下一批样本/增强、loss、模型、optimizer/scheduler 和 RNG；包含 epoch 边界。数值容差在比较前记录，不能只核验 loaded model 的推理。
- 固定报告全验证集零 flow 基线、初始模型和短跑模型；静止/运动区域及四个 stratum 分开诊断，双方使用同一物理 mask。整体 EPE 暂不优于零 flow 不能单独证明代码有错；但无法解释的物理错位、恒定伪流、参数不更新等必须先排除，不能用有限 loss/梯度代替正确性。
- 可用独立简易运动 fixture 做学习诊断，但不得因此改 generator 参数迎合结果；不把诊断中专门拟合的权重当正式初始化。若短跑本身就是登记正式训练的首个 epoch，全部契约通过后可从该 checkpoint 连续完成余下预算，避免白白重复已有效的更新。

## 放行必须由启动程序执行

交付机器可读的 `preflight_result.json`，包含每项的实际值、容差、PASS/FAIL/NOT_RUN、复现命令及证据路径；绑定实际代码、第三方补丁、环境、配置、bank/split/adapter manifest 指纹。不要仅手写一个总 PASS。

新的正常启动/恢复入口必须先验证该结果：缺失、失败、必要项未运行、指纹过期均以非零退出，**不得创建长训练进程**。加三项最小反例证明：缺报告、篡改配置/数据指纹、注入一个确定错误时都被拦住。源码、输入契约或数据变化时重跑对应测试；仅补文档不必重复全部计算。

研究目录的 `assess_captured_audit.py` 只负责判定本次已采集证据，**尚未接入生产 launcher**；这个最后的工程连接是本次明确交付项，不能声称已经存在。

正式运行首个 synthetic validation 就保存初始/零 baseline、分层指标和少量可视化；后续定期检查。触发 NaN、真实物理控制失败、配对失配、无参数更新、损坏 checkpoint 时停止受影响任务并保留现场；正常波动或某生成器暂时更好不构成停止理由。新增检查不使用真实数据，不把真实排名作为排错依据。

## 交付与并行安排

只需交付：修复摘要/补丁、新版本依赖与 hash、各层测试结果、阻断反例、配对短跑和真实 resume 证据，以及放行后正在继续的训练位置。失败应报具体检查和数值，勿只报“smoke passed”或“进程存在”。

互不依赖的环境、单元检查和模型入口可以并行；共享几何未通过前不能启动依赖它的长训练。E2VID/E-POSE 不因光流通过而自动放行：各自完成与输入/损失/指标相应的极小控制和正式入口短跑后自主推进，不等待三个任务一起完成。工程细节自行选择；仅冻结 core、模型/数据集/训练协议的方向性变化或持续无法解释的问题再上报。
