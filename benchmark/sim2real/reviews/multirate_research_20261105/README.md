# 减少中间采样开销的研究结论

2026年11月6日。供 Genesis Event Camera 插件效率支线决策使用。

**有值得验证的突破路线：让几何重建、传感器更新、事件时间精度分别安排。首选保留现有377步传感器与随机数网格，只减少昂贵的几何重建。文献和源码支持这种拆分，但尚没有本插件的测速或质量验收结果。**

## 用通俗的话解释

目前每10毫秒，要把“世界在这一刻长什么样”重新算377遍，再让传感器更新377遍。前一件事包含投影、深度竞争、覆盖和遮挡，远比简单更新一个像素状态昂贵。

377主要来自300Hz低通、显式Euler步进和0.05的步长限制。它约束传感器数值更新，并不天然要求几何层也做377次同样昂贵的工作。学界的共同启发是：先建立一段时间内亮度如何变化的表示，再由传感器消费它。事件时间还可以在区间内部计算，不必等于图像采样时间。

拟研究的第一步是：

| 每10毫秒 | 当前路径 | 首个研究原型 |
|---|---|---|
| 昂贵几何计算 | 377次全图查询 | 按运动、亮度和遮挡风险选节点，失败时细化或回退 |
| 传感器更新 | 377次 | 仍为377次 |
| 噪声与不应期代码 | 完整现有实现 | 继续使用完整现有实现 |
| 中间亮度 | 每步独立几何重建 | 安全段内便宜重建，风险段使用原查询 |
| 资格 | 已有指定配置与已测范围 | 新数值候选，单独验收 |

保留相同随机数不代表相同噪声事件：亮度会影响shot概率，信号事件也会影响不应期与噪声接受。因此第一步只隔离“几何输入发生近似”这一变量，不能宣称全管线等价。

## 三条路线的选择

**优先研究几何与传感器分频。** 先做全图时间节点，不恢复已淘汰的tile/prune方案。节点间的亮度重建必须检查深度顺序、覆盖变化、显露区域及内部亮度反转。端点甚至端点加中点相同，都不能证明中间没有短脉冲。没有保守依据的区间应回退；如果回退太多，加速假设即失败。

现有五类首区间中，非传感器采样需求最大为6、3、15、17、16，而传感器均要求377。它说明值得测试拆分，不能证明17个几何节点足够。377/17约22.2只是几何查询次数的示意比例，绝不是已测的整体加速倍数。数据来自既有[短检收据](../efficiency_continuation_20261105/evidence/zbuf_reuse/short_gates/reference/)。

**随后研究解析传播与阈值求根。** ICNS及线性系统精确积分给出依据，但我们的滤波系数随亮度变化；固定时间常数公式不能直接覆盖全区间。阈值复位、不应期、泄漏、shot及现有“先signal后noise”顺序也要定义清楚。这属于独立的新数值版本。

**更后面才研究按事件采样噪声。** 首次穿越、Poisson候选及counter-based RNG能减少空步/随机池，但会改变当前离散噪声、RNG映射或竞争过程。保留几个rate参数不足以证明保留完整噪声。

## 需要先解决的正确性问题

既有[独立采样诊断](../sampling_quality_20261105/SAMPLING_QUALITY_REPORT_ZH.md)显示，一个100ms真实Genesis片段从63加到754步，中间图像误差几乎不变。继续堆采样不能修复已有的重建误差。这一误差来源要与分频原型并行定位，并在解释新质量结果前区分。

该诊断也显示降低传感器步数会增加时间误差，377本身也未通过全部20微秒诊断预算。20微秒是本项目预算，既不是学界标准，也不能当作某项正式任务必然受损的证明。1ms真实渲染参考可以检查几何误差，尚不能当20微秒事件真值。

首个原型的代码边界、退化测试、独立参考和性能口径见[PROTOTYPE_SPEC.md](PROTOTYPE_SPEC.md)。本次只新增研究资料；未连接服务器、运行GPU实验或改任何生成器实现。
