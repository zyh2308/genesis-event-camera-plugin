# 执行指令：三线并行，优先补足场景与运动信号

这是本轮统一指令，覆盖同目录 `NEXT_EXECUTION_PROMPT.md` 与 `SCENE_UPGRADE_EXECUTION.md` 中不一致的任务顺序；旧文件保留作研究记录。你负责工程实现、实际运行和证据交付。常规兼容、环境、调度和脚本问题自行解决；训练目标/模型切换、冻结核心变更或无法消除的数据语义问题，带证据向研究会话汇报。

## 本轮的首要问题

用户明确担忧：之前自建的地面/方块场景过于简单，运动和纹理支持不足，既削弱实验说服力，也会干扰光流问题定位。

因此，**先证明训练场景确实提供足够的可观测运动，再判断网络、损失和事件生成器的表现**。场景看起来复杂、训练无报错、loss 下降、单样本能记忆，均不能单独满足这个要求。两生成器的目标是公平验证，不保证或强求 EventGenesis 胜出。

## 1. 光流：最高工程优先级

**先修入口，保留旧结果。** 已发现两个新短训入口问题：注册器和训练器把自身源码路径指向目录 `HERE`；模型指纹表使用 `models/steflow.py`，实际锁定源码为 `models/STEFlow.py`。在实际环境确认并修复，登记代码版本；走通真正的注册、前反传、checkpoint 恢复和普通 eval。不要把仅语法检查通过当成完成。旧 32-rollout 训练和已完成的八 rollout 方块 bank 保留为回归资产，不重生成，不再用其长期扩训替代场景改进。

**从成熟三维场景中抽样。** 优先验证 ReplicaCAD Interactive/PBR 的一个完整室内布局；可复用现有环境中来源清楚、质量合适且导入更方便的成熟资产。若遇到结构性阻碍，再评估 HSSD，避免同时维护多个新仿真平台。复用三维资产/材质/布局，在 Genesis 中生成物理轨迹和标签，不把下载的 RGB 视频称为 Genesis 物理 bank。

导入一个场景成功后，扩成少量场景 pilot，约三个可用场景/布局起步。先登记场景 ID、抽样种子和轨迹，不看模型或 generator 分数挑场景。按完整场景划分训练/验证，不能把同一连续轨迹的相邻窗口随机拆分；同一住宅的不同摆放不应被宣传为不同住宅泛化。

**必须具备两种运动条件。**

- 丰富静态室内场景 + 持续相机平移/旋转：先获得覆盖较广的可见运动、纹理与深度变化，定位原自监督目标是否能学习。
- 丰富场景 + 独立运动物体/遮挡：进一步检查物体运动和可见性；保留原解析平移/小场景作确定性回归。

复杂房间搭配静止相机仍可能没有运动。调整运动、距离和路径时，只依据共享几何、可见性、纹理和 GT 位移，不依据生成器排名。不靠加噪声或强行匹配事件数提高“活跃覆盖”。

**训练前，拿出真实场景证据。** 首个交付应尽快提供一段实际 Genesis 渲染视频/拼图，包含 RGB、深度、GT flow、两组事件；光流对比使用共同色标，并附相机路径。核对尺度、坐标、材质、纹理、遮挡、相机穿墙和有效区。记录实际 renderer 信号来源；8-bit display RGB 逆 gamma 不得称为原生 HDR。正式研究基线要求的原生信号不可获得时，明确说明影响并汇报，不静默替换。

同时按场景和运动类别报告：GT 位移分布、有效运动覆盖、纹理/运动交集，以及实际训练 crop/增强后还剩多少信号。两组事件支持单列诊断，不能按某组的事件多少筛选物理样本。验收规则在训练前登记，不使用模型效果定门槛；若有效信号仍稀少，先修场景/路径，不启动长训。

**信号达标后做配对短训。** 两生成器从同一物理 bank 分叉，共享标签、模型、初始化、表示、增强、样本顺序和预算。沿实际多尺度 loss 路径检查正确位移与零/反向位移的光度分量和梯度，不用另一个简化 warp 脚本替代实际优化目标验证。

先复用/更新已有 100-update 配对自监督诊断，作为首个运行交付。独立场景上同时报告 normal-events、zero-events、reverse-bins、零流基线，给出动态层与静态层的 EPE、预测/GT 幅值和方向。共同掩码由正常配对输入固定，保留空窗口。100 次不足以判断学习时，可事先登记有限延长预算并两组一致执行，不能把短训未收敛直接判为仿真器失败，也不能自动扩成另一轮长训。

正式扩训的建议应建立在独立合成场景上的有用运动响应，而非只看总 loss、单窗拟合或全图静态像素平均值。若仍退化，提交能够区分数据、实际 loss、表示/优化问题的证据和一个优先修复方向。改用合成 GT 监督或切换模型，属于新协议，不能悄悄混入原自监督实验。

## 2. 重建：独立完成现有版本首轮真实测试

不等待光流场景升级，不重跑已完成的两组 200 epoch / 12,000 updates。

沿上一版指令已接受的 HQF v3 规则，实际核对现有 synthetic-best 权重、数据、模型与代码 hash，保存冻结协议后，执行两组 seed 0 的 HQF 全 14 序列真实推理和评分。保持 event-only、序列重置、固定时间戳异常规则、原生画幅、固定输出范围、不做亮度拟合；LPIPS-Alex 主指标，SSIM/PSNR/MSE 辅助，先帧后序列等权聚合。交付逐序列和汇总结果，明确单 seed 与旧训练版本的边界。

新丰富场景的设计依据与本轮短训预算，应在查看真实分数前登记；HQF 结果只用于报告，不能用于调整场景、generator、checkpoint 或训练配方。若以后用新场景重训，使用新的已冻结版本，不能将同一真实集反复当作调参反馈。HS-ERGB 扩展准备并行处理，不拖住当前 HQF 交付。

## 3. 位姿：继续解除暂停，独立推进

E-POSE 全部原始 RAR 已上传。以当前导入状态和每包成功解压收据为准，使用最终目录中的已就绪物体，不读临时 `.extracting`，不重传或重复解压，不等所有派生包才开始。

复用已有 SingleShotPose/PnP 管线，先固定一两个身份/CAD 对应确定的物体，核对原始 HDF5、MAT、K、时间、长度单位、物体与相机坐标、CAD 原点；给出投影自洽证据。真实模型接口必须基于原始全帧事件和预先声明的可用先验，不能使用 GT crop/mask/box、GT 选点或 GT 挑 PnP 解。特别审核 MAT 中 events 是否属于 GT 分割事件。
