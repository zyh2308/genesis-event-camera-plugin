# v5输出文件封存修复

父会话确认v4在g1完成18序列、20916个原生packet的全部内容准备，但随后在加载任何候选模型前被manifest SHA核查拦下。

根因是我实现prepare时，在JSONL输出流仍位于`with ... open('x')`内部时计算文件SHA。Python缓冲区的最后一段尚未落盘，因此记录的hash对应不完整文件；函数返回后关闭流，完整文件的hash自然不同。它不是原始事件、标签或真实分数发生变化。

v5将序列登记移到整个`with`结束之后。输出JSONL和输入HDF5先关闭，再计算并注册SHA；模型、输入、几何、指标和原始样本选择均不变。旧版和失败证据保留，不能修改旧protocol让错误hash悄悄通过。

新增回归夹具在prepare函数实际返回之后，独立打开每个已登记JSONL文件，重算完整SHA并读取实际行数，与protocol逐一对照。相同夹具成功抓住未修改v4的错误，v5全部通过。数值、非刚体GT、重复时间戳边界和人造完整接口夹具继续通过。

其他输出hash时序已只读审阅：`dump()`内部关闭文件后才返回，interface_preflight、metric_fixture、protocol的hash均在其dump返回后计算；CAD及物理HDF5是只读输入且在封存前已关闭。未发现另一处输出仍写入时提前计算SHA的问题。

正式v5需新输出目录完成prepare并重新授权。v4阶段没有候选真实分数，不能据此声称真实实验完成或产生排名。
