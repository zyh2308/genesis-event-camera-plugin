两组sigmoid都没有大面积饱和：600步平均导数约0.247/0.246，输出落在0.02以下或0.98以上的比例均为0%。因此没有“饱和压死梯度”的证据；导数上限0.25本身也不是饱和证据。

训练到600步比300步降低了四臂的感知误差，但线性臂追赶更快，sigmoid的感知优势缩小，不能据600步外推最终胜负。原连续sigmoid日志3900→5100仍有下降和波动；4,800步是已选VGG最优点，其后单点回升不能证明训练已到平台。

细节影响并非所有方法一致：EventGenesis的SSIM与边缘幅值降低，V2E的边缘幅值却略升。更明确且一致的是两组sigmoid的PSNR降低约1dB、MSE增加约23%/25%。这反映感知指标与逐像素光度误差的取舍，不足以证明永久容量上限，也不能解释全部真实域差距。

## 执行与配对核验

- 四臂从同一注册参数初始化开始；原Adam、loss、有效batch2×40、采样索引和实际标签/增强序列保持相同。跨生成器事件不要求相同；同一生成器内两激活的事件摘要必须相同。
- 新诊断采样RNG固定70000，是独立配对cohort，不能冒充旧正式训练的前600步。一次连续训练到600；验证前后保存恢复Python/NumPy/Torch/CUDA RNG。
- 每一步检查30个有限梯度张量、76次有效TC调用及非零梯度。不会因线性臂变黑/平坦而提前排除，只在非有限数值等安全错误时停止。
- 检查点含参数、optimizer、RNG和游标；实际核验CPU读回参数SHA与RNG，optimizer计数从运行对象核对。本轮未声称做过独立进程或完整optimizer恢复训练核验。
- 现存4,800步与5,264/5,306步权重只重评、不续训；原线性12,000/11,400步仅作历史参考，不是等预算激活控制。
- 4,800步是历史VGG最佳点，之后局部回升可能有选最优后的偏差；原连续训练完整VGG历史与按时间固定的末5点趋势一起保留。
