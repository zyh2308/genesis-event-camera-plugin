# E-POSE public-access check

This audit was performed on 2026-10-19. A fresh WSL recheck at 09:15 UTC confirmed the official Springer Nature Figshare article JSON/API/downloader paths still return HTTP 202 with an empty body, and the plain Figshare API returns 403. I did not retry these endpoints in a loop. The public DataCite API did return the DOI metadata and reports the dataset size as 29,759,153,475 bytes, but it does not expose a file listing or sample download URL. The official E-POSE GitHub API was reachable and lists 25 mesh files across 13 object-name folders, but contains no raw event HDF5 or per-sample MAT annotations. The model-to-sample match therefore remains unverified.

The paper states that raw data are HDF5 and pose annotations are in MAT files; the official code README says its existing scripts currently read bag files and have not yet been adapted to the provided HDF5. It reports 306 sequences, so a single sequence would be much smaller than the complete 29.8 GB archive, but the current access route does not reveal the per-file layout needed to request that subset. We still need one named original HDF5 sequence and matching MAT file to check timestamps, K, coordinate frames, CAD scale, and symmetry. Generic-cuboid synthetic checks remain mechanism-only and cannot stand in for E-POSE evaluation.

Fresh checks and their response metadata are recorded in `epose_access_recheck_20261019T0915Z.json`. The public Figshare access failure is a network-path blocker, not evidence that the dataset is unavailable; official metadata and the paper continue to identify the public record.

Sources: [E-POSE paper](https://doi.org/10.1038/s41597-025-04536-5), [official data record](https://doi.org/10.6084/m9.figshare.28106717), [official code and geometry repository](https://github.com/oussamaabdulhay/E_Pose).
