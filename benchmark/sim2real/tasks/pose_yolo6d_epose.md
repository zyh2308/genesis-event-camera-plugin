# Object-pose route: YOLO-6D → E-POSE

Status: static source contract is checked; Stage-2 generic-box pilot is implemented but has not yet run. No raw E-POSE sample has been obtained, so the dataset-specific loader and CAD interface remain unresolved.

- Pinned candidates: `microsoft/singleshotpose@2c282619101f9f31666dd18b42393375bea1600f`; E-POSE annotation source `oussamaabdulhay/E_Pose@b96ae783fcb6de84e1e9c602e91bce941cab0234`.
- Full pinned source snapshots are present on g1. E-POSE repository provides annotation tooling rather than a complete downstream trainer; SingleShotPose's path is LINEMOD/RGB/mask/crop based.
- The pinned model config accepts a three-channel 416×416 full-frame tensor. The bundled dataset.py train path calls load_data_detection, which reads RGB and applies GT-mask background compositing; the validation path loads RGB. Neither bundled loader is valid for this experiment. The route-local pilot instead constructs three fixed-scale channels from raw event counts and uses the original SingleShotPose projected-centroid/eight-cuboid-keypoint label layout and RegionLoss target builder. It never supplies RGB, GT mask/crop/box, segmented events, depth, segmentation, or pose as inference input.
- The E-POSE paper reports per-window MAT fields for raw events, T_dvs^obj, IntrinsicMatrix, T_base^dvs, time, keypoint projections, and class index. Its dataset description reports 10 ms windows and 306 sequences. These are publication-level facts, not an inspected archive sample. The pinned E-POSE README says the released H5 files still need adaptation before the checked MATLAB scripts can consume them directly. MATLAB utilities also contain hardcoded K values; those are not substituted for per-sample calibration.
- A short generic-cuboid closure is configured in configs/pose_stage2_pilot.json and scripts/run_pose_stage2_pilot.py: paired 10 ms full-frame event tensors, shared Genesis pose/K keypoints, whole-rollout train/validation split, paired initialization, two epochs, and checkpoint restore. It exercises the mature network/loss interface but does not establish an E-POSE object-class/CAD match.
- The publisher record lists a 27.72 GB archive; it was not downloaded. No real pose scoring or real-data checkpoint selection is performed. The raw sample's event ordering/polarity/time units, K convention, pose axes/units, and sync remain unverified.
- Next, inspect one released H5/MAT plus its object CAD; then bind the event encoder and shared synthetic trajectory to that class and verify its annotation convention before approving any real evaluation entry. GT masks, crops, segmented events, LINEMOD validation, or real-data checkpoint selection cannot become model inputs or selection signals. E-POSE is not declared unavailable; this is a sample-contract and CAD-matching gate.
