# Reproducing the qualified comparison

Use the immutable release tag and archived input/weight manifests. Do not run directly in a training checkout or reuse this experiment's historical GPU reservation record.

1. Verify availability and ownership of the desired GPU through the existing project coordinator; use a new run ID and an isolated output directory. The original experiment used g1 GPU 2, V100S, Torch 2.8/CUDA 12.6, 2 Torch/OMP threads and 1 OpenBLAS thread.
2. Copy this directory's scripts into the new run directory. Stage the versioned `frozen_versions/eventgenesis-gpu-stage9-20261105` package there as `release_candidate_static` (a read-only link to the immutable package is sufficient). Historical verification scripts intentionally retain the exact original paths, output names and failed-attempt dependencies; follow the final accepted scripts for new executions.
3. Keep the physical bank, pinned v2e source/weights and old frozen long oracle at the locations indexed in `external_artifacts.json`, or explicitly version any path adaptation. Verify the archived source/weight/physical hashes. No real test data is required.
4. Set `CUDA_VISIBLE_DEVICES` to the coordinated UUID. Use `build_release.py` with the existing isolated compiler, or provide a compatible private compiler/build directory. Never install into the shared environment or write into the frozen package.
5. `final_measurement_driver.py` runs the actual integrated package against v2e with 20 intervals, the five fixed cases and three repetitions; `analyze_comparison.py` produces the raw CSV and scene-level analysis. Output directories must not already exist.
6. The separate controls include the stock CLI, automatic flow-based upsampling, fixed factor400, longer batch16 and a common-frame sensor comparison. Automatic sampling uses a different frame density and is not pooled into the matched-density speedup.
7. `native_acceptance_driver.py` uses the established private Mesa runtime for native HDR, CPU physical/render stage and CUDA event generation. The HDR stress uses the existing renderer-context lighting API, rather than an invalid VisOptions ambient value above1. Renderer sources are not changed.
8. Component acceptance verifies the actual CUDA sensor, holes/HDR/strict rejection, NumPy API/lazy diagnostics, restore, explicitly active capture and recorder output. The continuous regression additionally checks the saved frozen one-second oracle and fixed count-voxel/localization checkpoint. Preserve the separate strict raw float failure; these checks do not prove universal bitwise determinism or downstream accuracy.

Main elapsed time excludes model/process initialization, Genesis rendering, input loading and output file writes. Both standard serialization and worker total memory are retained alongside the declared metrics. The final metrology unregisters v2e atexit cleanup callbacks between trials/cases so abandoned model/state objects do not accumulate; EventGenesis memory excludes the unrelated v2e model held in the measurement process.

The full run's failed packaging/profile-guard/render-test setup attempts remain in the evidence, with distinct logs and receipts. They were blocked before final acceptance and are not substituted into the final performance table. Current training sources, configurations, events and checkpoints were not switched.
