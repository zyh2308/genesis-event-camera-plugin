# 仿真器计算优化：独立候选与复现实验

本目录是冻结核心之外的研究实现，不是正式实验的新冻结版本。实际测试服务器为 g1，GPU 2 为 Tesla V100S 32GB。正式三线训练、已生成的数据和真实测试协议没有接入这些候选。

完整 200ms 回放的严格逐位门禁保留失败：事件位置、极性、顺序和数量相同，160 个时间戳最大相差约 0.177 纳秒。相同中间帧下的 200ms 传感器对照则全部逐位一致。后续归因与下游输入回归单独记录，不将原门禁重标为通过；正式发布前需按实际允许的数值契约处理原有几何重复波动。

## 实现范围

- `candidates.py`：保留原始采样与几何公式。`fused` 将每个像素的传感器时间递推融合为 CUDA kernel；随机张量仍通过原始 Torch generator、原始调用顺序和 dtype 生成。
- `fused_early`：在传感器融合之外，缓存同一区间的端点 log 图、批量传出中间帧，并在几何投影候选已全部处理后结束空迭代。
- `fused_chunk`：用原始函数分块处理几何时间维，降低峰值显存；没有删除时间采样点。
- 保留 FP64 几何输入与传感器状态、377 个中间时间点/10ms、阈值不一致、泄漏、散粒噪声、不应期、事件数量以及 unknown/support 掩码语义。
- 只支持本次 Stage 9 完整传感器配置。其他光电噪声、标定噪声图、非理想 readout 等功能没有关闭后冒充受支持；不支持时明确拒绝。
- 零斜率的全局事件时序特殊情况、容量越界等触发完整原版回退。回退前恢复 RNG，且不提交候选状态，不静默截断事件。

## 文件版本

`v1` 保存第一轮完整五场景、每方案五次重复时执行的代码。`v2` 的唯一传感器改动是：按当前输入区间长度和不应期推导事件缓冲区上界，避免静止像素的历史时间戳导致缓冲区随 episode 年龄增长。该改动另有独立进程恢复及古老时间戳回归测试，并重做了五场景三方案配对计时。

几何适配使用进程内受限替换并在 finally 中恢复，仅在本轮独立、单线程模拟 worker 中测试。多进程测试使用各自独立 Python 进程；本实现尚未作为多线程公共插件 API 发布。

## 复现入口

先按项目已有规则取得专属 GPU 预约，再使用记录中的 Torch 2.8 环境和独立目录。构建只写该目录的 `build/`，不修改共享 Python 环境或冻结核心。当前 CUDA 构建目标为 sm70，其他 GPU 需重新构建并复核。

```text
python build_fused.py
python test_sensor.py
python test_actual_inputs.py
python test_process_resume.py
python test_geometry.py
python paired_suite.py baseline,fused_early,fused_chunk paired_suite 3
python analyze_v2.py
python test_model_regression.py
python test_worker_throughput.py
```

输出目录默认要求尚不存在；不要覆盖已完成证据。运行环境、冻结核心和缓存数据的绝对路径保留在测试脚本及交付清单中。二进制、原始 NPZ、检查点等外部产物以路径、大小和 SHA256 索引，轻量结果随报告入库。

## 计时口径

输入来自已有物理缓存，读取发生在计时之外。测量原始 public capture 调用，包含中间几何、传感器和 CPU 事件序列化；初始化、Genesis 渲染、缓存读取和保存测试结果不计入。每次测量前有一次预热，CUDA 同步后读取墙钟。方案执行顺序交替，原始每次数据均保留。

因此这些数值衡量缓存回放到事件的成本，不是 Genesis 全管线实时率，也不是当前离线训练的每步提速。固定定位模型回归用于检查优化有没有改变输入和位置预测，不是准确率提升证据。
